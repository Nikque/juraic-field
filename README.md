# Juraic Field

[English README](README.en.md)

Juraic Field は、落ちものパズルの対戦・練習ソフトです。1 人で連鎖を組む「とこ」、同じ PC での 2 人対戦、対戦 AI「Juraic」との対戦、AI どうしの観戦、ネット対戦（人 対 人）、リプレイの保存と再生、連鎖の盤面を作るジェネレーターが入っています。Windows 10 / 11（64 ビット）用、Linux（x86-64）用、macOS（Apple シリコン）用、Android（arm64）用があります。

- `JuraicField.exe`（Linux 版は `JuraicField`、Mac 版は `JuraicField.app`）: ゲーム本体
- `JuraicFieldGenerator.exe` / `random_19_chain.exe`: 連鎖盤面ジェネレーター（GUI / CLI。GUI は Windows 版だけ）

ルールは「ぷよぷよ通」に合わせてあります。Juraic Field は個人が作った非公式のソフトで、株式会社セガとは関係がありません。「ぷよぷよ」は株式会社セガの登録商標です。

## 入手と起動

1. [Releases](https://github.com/Nikque/juraic-field/releases) の zip を新しいフォルダーに展開します（zip の中から直接は起動しないでください）。
2. `JuraicField.exe` を起動します。インストールも追加のランタイムも要りません。初回は Windows の警告（発行元不明）が出ることがあります。
3. メニューから選びます。キーやコントローラーの割り当ては、メニューの「操作の割り当て」で確かめて変えられます。

やめる時は、展開したフォルダーごと消せば元に戻ります（レジストリなどには何も書きません）。設定とキーの割り当ては、exe と同じフォルダーの `JuraicField.ini` に保存されます。最初の状態に戻したい時は、このファイルを消してください。

### Linux 版

1. Releases の `juraic-field-…-linux-x86_64.tar.gz` を展開します（`tar xzf juraic-field-…-linux-x86_64.tar.gz`）。
2. 展開したフォルダーで `./JuraicField` を起動します。インストールは要りません。

- Ubuntu 22.04 以降と同じ世代の Linux（glibc 2.35 以降）で、X11 か Wayland のデスクトップで動くはずです。音は PulseAudio・PipeWire・ALSA のどれかで鳴ります。
- 遊べる中身は Windows 版と同じです（盤面ジェネレーターの窓だけは無く、CLI の `random_19_chain` が入っています）。設定ファイル・リプレイ・操作の割り当ては Windows 版と同じ形で、そのまま使えます。
- 自分の絵は png・jpg・bmp、曲は mp3・wav・flac が読めます（Windows 版より少なくなります）。
- 画面の文字は同梱の BIZ UDPゴシックで描きます。
- **確かめたのは Windows の WSL（Ubuntu 22.04、WSLg）の上だけです。** 実機の Linux とコントローラーでは、まだ確かめていません。Windows 版とのネット対戦は、同じ PC の中（WSL の Linux 版が部屋を立て、Windows 版が入る）で、台本どうしの対戦が最後まで同じに進むことを確かめました。2 台の PC の間と、人が画面で操作する対戦は、まだです。

### Mac 版

1. Releases の `juraic-field-…-macos-arm64.zip` を展開し、`JuraicField.app` を好きな所に移して開きます。Apple シリコンの Mac（M1 以降）、macOS 11 以降用です。
2. Apple の開発者の署名と公証を受けていないので、最初は「開発元を確認できない」などと出て開きません。「システム設定」→「プライバシーとセキュリティ」の下の方の「このまま開く」を押すと、開けるようになります。

- 設定・リプレイ・自分の絵と曲は `~/Library/Application Support/JuraicField` に置かれます（形は Windows 版と同じです）。読める絵と曲の形式は Linux 版と同じです。
- **確かめたのは GitHub の Mac のビルド機（Apple シリコン）の上だけです**: ビルド、テスト（Windows で保存したリプレイの再生を含む）、AI どうしの対戦のチェックサムが Windows と同じこと、窓を出さない自己テストの画像（Linux 版とバイト単位で同じ）。人が Mac で窓を開いて遊ぶこと、音、コントローラーは、まだ確かめていません。

### Android 版

入れ方・つなぎ方・操作は、Releases に APK と並べて置いた `juraic-field-…-android-readme.txt` に詳しく書いてあります。

1. Releases の APK を Android の端末で開いて入れます。初めての時は「この提供元のアプリを許可」の確認が出ます。Android 8 以降、arm64 の端末用です。
2. コントローラー（USB-C や Bluetooth でつなぐもの）かキーボードで遊びます。画面に触れての操作はありません（ネット対戦の名前とアドレスの入力の時だけ、画面のキーボードが出ます）。端末の戻るボタンは Esc と同じです。

- 画面は横向きです。同梱の絵・曲・フォントは、初めて開いた時にアプリの中に取り出します（少し時間がかかります）。
- 設定・リプレイ・自分の絵と曲は `Android/data/io.github.nikque.juraicfield/files` に置かれます（ファイル管理のアプリや、USB でつないだ PC から届きます）。読める絵と曲の形式は Linux 版と同じです。
- スマートフォンの CPU では、AI の 1 手の時間の中で探索が狭まり、同じレベルでも弱くなることがあります（見込み。レベルの中身は同じです）。
- **確かめたのは GitHub のビルド機の上だけです**: APK を作れること、エミュレーター（x86_64、Android 14）で開いてメニューが描かれ、45 秒動き続け、音の出口が開き、絵・曲・フォントが取り出されること。実機、コントローラー、キーボード、音を聞くこと、対局、ネット対戦は、まだ確かめていません。

## 遊び方

### メニュー

| 項目 | 内容 |
| --- | --- |
| とこ（1 人プレイ） | 1 人で連鎖を組みます。1 手戻す、同じツモでやり直す、盤面ファイルからの練習、連鎖の予測表示があります |
| 対戦（2 人） | 同じ PC で 2 人が対戦します |
| 対戦（人 対 AI） | 対戦 AI「Juraic」と対戦します。人が 1P です |
| 観戦（AI 対 AI） | AI どうしの対戦を見ます |
| 実機の 2P を Juraic が操作 | Windows 版だけ。実機の 2P を Juraic が仮想のパッドで操作します（下の「実機の 2P を Juraic が操作」） |
| ネット対戦（人 対 人） | 2 台の PC を直接つないで対戦します（下の「ネット対戦」） |
| リプレイを見る | 保存したリプレイを再生します |
| 設定 | ルール、操作、AI、表示と音 |
| 操作の割り当て | キーボード 2 組とコントローラーの割り当て |
| 盤面ジェネレーター | `JuraicFieldGenerator.exe` を開きます |

### 操作（最初の割り当て）

| 操作 | キーボード 1 | キーボード 2 |
| --- | --- | --- |
| 左右に動かす | ← → | A D |
| 速く落とす | ↓ | S |
| 左回転 / 右回転 | Z / X | F / G |
| 一時停止 | P | T |

コントローラー（Xbox 系とそれ以外）も使えます。割り当てはメニューの「操作の割り当て」で変えられます。Windows 版では、PlayStation のパッドと Switch の Pro コントローラー・Joy-Con を SDL 3 で読み、Xbox 系と同じくボタンの位置で扱います（下のボタンが左回転、右のボタンが右回転）。設定の「クイックドロップ」を「あり」にすると、上（キーボード 1 は ↑、キーボード 2 は W、コントローラーは上）が「一気に落とす」になります。「なし」の時、とこでは ↑ でも右回転できます。

とこでは、Backspace で 1 手戻す、R で同じツモでやり直す、N で新しいツモ、O で盤面ファイルからの練習、E で空の盤面、Ctrl+C / Ctrl+V でシードのコピーと貼り付け、F5 でリプレイの保存ができます。盤面ファイル（ジェネレーターの `.jfchain`・`.jfboard`）は、ウィンドウにドロップしても開けます。

### 設定

設定は 4 つの部に分かれています。左の一覧を ↑↓ で選び、Enter か → で中に入ります。中では ↑↓ で選び、←→ で変えます（どのキーも、押したままにすると少し待ってから続けて動きます。値は端まで行くと反対の端に戻ります）。灰色の項目は、今のほかの設定では使われない項目です。

| 部 | 項目 |
| --- | --- |
| ルール | 色数（3〜5）、消せる個数、ツモ補正、ゲームスピード、落下ボーナス、おじゃまレート、マージンタイム、連鎖しばり、全消しボーナス、1 回に降るおじゃまの上限、先取本数、先取セット数、ネット対戦の遅延 |
| 操作 | 先行入力、斜め入力、クイックドロップ |
| AI | 探索（自動 / 手動）と幅・深さ・仮のツモ列の数・スレッド、判断を始める時点、持ち時間、積みの手で本線を撃つか、AI の種類とレベル（2P 側、観戦の 1P 側） |
| 表示と音 | 効果音の音量、連鎖の予測表示、着地位置の表示、背景（1P 側・2P 側・それ以外）と暗さ、BGM（対戦・とこ・メニュー）と音量 |

「先取本数」は 1 セットを取るのに要るラウンドの数、「先取セット数」は対戦に勝つのに要るセットの数です（最初は 2 本先取の 1 セット。どちらも 99 まで）。対戦の画面では、取った数を 2 つのフィールドの間に出します。5 までは印（★ と ◆）の並び、それより多い時は「★ 取った数 / 要る数」の数字です。

### リプレイ

- 対戦が終わると、リプレイが exe と同じフォルダーの `replays` に `.jfreplay` で保存されます。とこでは F5 で保存します。
- メニューの「リプレイを見る」で選ぶか、ファイルをウィンドウにドロップすると再生できます（ネット対戦の間は、ドロップしたファイルは開きません）。Space で一時停止、→ を押している間は 4 倍速、R で最初から、です。
- リプレイは、ツモの種・ルール・毎フレームのボタンだけを記録した文字のファイルです。同じ種とボタンから同じゲームになることを使っています。

### 背景と BGM

- 絵 3 枚と曲 9 本が付いていて、最初から使われます（リポジトリでは `media/`。ビルドすると exe の隣の `background`・`bgm` に写されます。作り方とライセンスは [media/README.md](media/README.md)）。
- 背景は 3 か所（1P 側のフィールド、2P 側のフィールド、それ以外）を別々に選べます。BGM は 3 つの場面（対戦、とこ、メニューなど）を別々に選べます。
- 自分の画像や曲を使いたい時は、exe の隣の `background` の中の `1p`・`2p`・`other`、`bgm` の中の `versus`・`toko`・`menu` のフォルダーに置くと、設定で選べます。画像は png・jpg・bmp・webp、曲は mp3・wav・m4a・aac・wma・flac です（ogg は読めません）。曲は繰り返し鳴ります。

## 対戦 AI「Juraic」

- 相手の盤面と見えているツモを読んで打ちます。連鎖を組み、相手の攻めには返し、勝てると読めば先に撃ちます。
- 打ち方の違う 2 つから選べます。
  - **Juraic 催促（小）**: 自分の盤面が埋まってきたら、本線を残したまま小さい連鎖で攻めます（最初はこちらです）。
  - **Juraic 催促（極小）**: 自分からはほとんど攻めず、本線を育てて撃ちます。
- 強さを 36 段階から選べます（最初は Lv 36）。Lv 1〜9 超初心者用 ／ Lv 10〜20 初心者用 ／ Lv 21〜25 初〜中級者用 ／ Lv 26〜30 中〜上級者用 ／ Lv 31〜35 上級〜超級者用 ／ Lv 36 超級者用。レベルが下がるほど、置くのがゆっくりになり、相手の盤面を見るのが遅れ、先を読む量が減ります。隣どうしのレベルは、上のレベルが 6 割ほど勝つ差になるように、「催促（小）」どうしを対戦させて決めました（「催促（極小）」のレベルは同じ設定を当てはめたもので、測ってはいません）。
- 人 対 AI と観戦では、対戦が終わった画面で、AI の種類とレベルをマウスのクリックで変えられます（次の対戦から変わります。レベルは、ボタンを押したままにすると続けて変わります）。
- 考えるのに CPU を 24 スレッドまで使います（PC の論理コアの数より 2 つ少ない数まで。論理コアが 8 未満の PC では 1 つ少ない数まで）。1 回の判断は 180 ms までに収めるようにしてあり、遅い PC では探索を狭くします。AI の考える時間が足りなかったラウンドの後は、画面の上に「処理落ち: AI が弱くなった可能性」と出ます。
- 測定の例: 公開されている AI「[Ama](https://github.com/citrus610/ama)」を毎回同じ手を打つようにした相手に、Lv 36 の「催促（小）」が 1,440 ラウンドで 1,093 勝でした（2026-10-14 の版、測定用の探索の大きさで）。この測定に使ったツール（Ama を相手の席に座らせるプログラムと、毎回同じ手を打つようにした Ama）は、このリポジトリには入っていません。
- AI の一部は Ama に倣っています。どこが該当するかは [licenses/Ama-NOTICE.txt](licenses/Ama-NOTICE.txt) にあります。

## 実機の 2P を Juraic が操作（Windows 版、試し）

- 同じ PC で動かしている実機のオフラインの 2P 対戦で、実機の窓の画面を読み、2P を Juraic が仮想のパッドで操作します。1P は人です。オンラインの対戦では使えません。
- メニューの「実機の 2P を Juraic が操作」を開くと、実機の窓を探し、2P の欄・キャラクター・操作の種類を選び、対戦が始まると 2P を操作します。AI の種類とレベルはこの画面で変えられます（開くたびに設定の 2P 側から始まります）。
- 13 段目（画面に出ない段）へ組を上げる動き（クイックターン、13 段目への床蹴り）は、ほかの置き場がどれも 3 列目を埋めて負けになるときだけ使います。この画面の「13 段目を通る動き」で「使う」に切り替えられます（開くたびに「使わない」から始まります）。
- 仮想のパッドには ViGEmBus のドライバーが要ります。このソフトには入っていないので、使う人が入れてください。
- **このモードの Juraic は、この作品の中の対戦の Juraic より弱くなります。** 盤面と組を実機の画面から読むので読み違いや読めない間があり、パッドの押しが実機に届くまでの遅れや、押し方・時間の扱いの違いもあります。上のレベルの強さや測定の例は、このモードには当てはまりません。実機での勝率は測っていません。
- 不具合を調べるための部分（読みの記録（exe の隣の `realgame\<日時>`、1 回で 2 GB を超えることがあります）、S キーでの実機の画面の保存、表のファイル `realgame_layout.txt`、画面の内部の数字）は、CMake の `JURAIC_REALGAME_DEBUG=ON` で組み立てた時だけ入ります。配布物には入っていません。

## ネット対戦（人 対 人）

- 2 台の PC を直接つないで対戦します。片方が「部屋を立てる」、もう片方が相手のアドレスを入れて「部屋に入る」を選びます。相手を探す仕組み（待合室など）はありません。アドレスは、相手と連絡を取って教え合ってください。
- 立てた側が 1P、入った側が 2P です。ルール（設定の「ルール」の項目と、「操作」の「先行入力」「クイックドロップ」）は、立てた側のものを使います。2 人とも同じ版の Juraic Field が要ります。
- 名前とアドレスは、その行で Enter を押してから入力し、Enter か Esc で終わります。アドレスは Ctrl+V で貼り付けられます。アドレスは ● で隠して表示します（F1 で表示と隠すを切り替え。配信に映したくない時のため）。
- 対戦中は一時停止できません。キーボードの Esc を 2 回押すと退出します。対戦が終わった画面で 2 人とも決定を押すと、もう一度対戦します。

**通信の遅れについて**

- 自分の操作はすぐに画面に出ます。相手の盤面は少し前の姿が見えます。
- おじゃま（予告・相殺・確定）は、画面の上に出ている「遅延 n フレーム」のぶんだけ遅れて効きます（60 フレーム = 1 秒）。相殺の決まりは 1 台の時と同じなので、同時に撃ち合っても、おじゃまが両方に残ることはありません。
- n は、つないだ時の回線の速さから自動で決まります（設定の「ネット対戦の遅延」で 1〜30 に固定もできます）。
- 相手の操作が届くのが遅れると、届くまで自分の側も止まります（長く止まる時は「通信を待っています…」と出ます）。8 秒のあいだ何も届かないと「相手との通信が途切れました」と出て、対戦は終わります。ウィンドウを動かしたり大きさを変えたりしている間は、通信も止まります。

### つなぎ方（部屋を立てる側の準備）

使う通信は UDP のポート 50777 です（立てる側が待ち受けるポート。`JuraicField.ini` の `netPort=` で変えられます。入る側は、ポートが 50777 でない時だけ「アドレス:ポート」の形で入れます）。入る側は、準備は要りません。立てる側は、相手の PC から自分の PC に通信が届くようにしておく必要があります。

1. **Windows のファイアウォール**: 初めて「部屋を立てる」を選んだ時に、Windows が確認を出すことがあります。「アクセスを許可する」を押してください。確認を閉じてしまった時は、Windows の「設定」→「プライバシーとセキュリティ」→「Windows セキュリティ」→「ファイアウォールとネットワーク保護」→「ファイアウォールによるアプリケーションの許可」で、`JuraicField.exe` に印が付いているか確かめてください。
2. **同じ家・同じネットワークの中で遊ぶ時**: ルーターの設定は要りません。立てる側は、部屋を立てた画面で F1 を押すと出る「この PC のアドレス」（192.168.… など）を相手に伝えます。
3. **別々の家から遊ぶ時（ポートの開放）**: 立てる側の家のルーターに、「外から UDP のポート 50777 に来た通信を、ゲームを動かす PC へ渡す」設定を入れます。この機能は、ルーターによって「ポート開放」「ポートフォワーディング」「ポートマッピング」「静的 IP マスカレード」「仮想サーバー」などと呼ばれます。画面の名前や場所はルーターごとに違うので、お使いのルーターの説明書も見てください。
   1. ゲームを動かす PC のアドレスを調べます。ターミナル（コマンド プロンプト）で `ipconfig` と入れ、「IPv4 アドレス」（例: 192.168.1.20）と「デフォルト ゲートウェイ」（例: 192.168.1.1）を控えます。
   2. ブラウザーのアドレス欄に「デフォルト ゲートウェイ」の数字を入れてルーターの設定画面を開き、管理者の名前とパスワードで入ります。
   3. ポート開放の項目に、プロトコル UDP、ポート番号 50777（外側・内側とも）、転送先 = 1 の IPv4 アドレス、を登録します。
   4. 相手に伝えるのは、1 のアドレスではなく、家の外から見たアドレス（グローバル IP アドレス）です。ルーターの設定画面の「WAN 側 IP アドレス」などの欄で分かります。
   5. 相手はそのアドレスを「相手のアドレス」に入れて「部屋に入る」を選びます。
4. **ポートの開放ができない・しても届かない時**: 集合住宅の共用回線、携帯電話の回線、「v6 プラス」「DS-Lite」などの方式の回線では、IPv4 のポート開放ができないか、使えるポートの番号が限られていることがあります。その時は、VPN（離れた PC どうしを同じネットワークにいるようにつなぐソフト）を 2 人とも入れて VPN の中のアドレスを使う方法、2 人とも IPv6 が使える回線なら IPv6 のアドレスを使う方法（ルーターの IPv6 のフィルターで UDP 50777 を通す設定が要ることがあります）、立てる側と入る側を入れ替える方法があります。

グローバル IP アドレスは、配信や公開の場に出さないでください。遊び終わったら、ルーターに登録した設定は消しておくと安心です。

## 連鎖盤面ジェネレーター

3〜5色で、最後の1組を置くと指定どおりに連鎖する1〜19連鎖の盤面をランダムに生成するC++20プログラムです。成功した盤面のURLを `19chain_urls.txt` に追記します。初期設定では、19連鎖・76個・4色の新しい盤面を100件生成します。設定で盤面を10列×18段に変えると、1〜47連鎖の盤面を生成します（下の「10列×18段の盤面」）。

盤面処理はすべてビットボード（1列16bit × 6列を1本のSSEレジスタに入れ、3本で色を表す48バイトの盤面）で行います。同じ盤面コア（`core/`）を、1 人プレイ・対戦・AI でも使います。

### Windows GUI

`JuraicFieldGenerator.exe` で設定編集・生成中断・結果選択・6×13盤面と10×19盤面・連鎖の再生を利用できます。CLI（`random_19_chain.exe` / `run.cmd`）も利用できます。操作、保存先、ビルド、対応範囲は [GUI_README.md](GUI_README.md) を参照してください。
GUIの盤面URLは、外部の連鎖シミュレーター 3 つの形式（画面の表示は 石川・対戦パーク・mattulwan系（pndsngミラー））から選べます（[URL_FORMATS.md](URL_FORMATS.md)）。
盤面編集、元に戻す・やり直し、編集盤面の連鎖再生と保存・読込に対応しています。通常5色に加え、おじゃま・得点・かた・鉄・壁を扱います。これらはランダム生成には含めません。

CLIのexeの直接実行でも日本語を表示できます。コンソールが接続されている場合は実行中だけ出力文字コードをUTF-8にし、終了時に元へ戻します。ファイルへリダイレクトしたログもUTF-8です。Windowsの設定パスには日本語や絵文字も使えます。URLファイルの最終行に改行がない場合も、次のURLを別の行に追記します。

### 生成される盤面の条件

出力する盤面は「最後の1組を置いた直後」の盤面です。次の条件をすべて満たします。

1. 6列×13段。どの列にも空洞がなく、14段目には何も置きません。
2. 発火すると、指定した連鎖数ちょうどの波が起き、各波は**同時消しなしの単独4個消し**です。
3. 13段目は連結・消去に参加せず、下のピースが消えると落下します。
4. 連鎖が終わった盤面で、左から3列目・下から12段目（組の出現位置）が空いています。
5. 盤面の個数は `4 * target_chain + extra` です。`extra` は `min_extra_pieces` から `max_extra_pieces` の範囲で選び、連鎖後にその個数が残ります。
6. **最後の1組**が1つ以上あります。最後の1組とは、盤面の最上部の2個（同じ列の上2個、または隣り合う2列の最上段1個ずつ）で、次を満たすものです。
   - その2個を除いた盤面では何も消えない。
   - その2個を除いた盤面で、3列目12段目が空いている（次の組が出現できる）。
   - その置き方に組が届く（下の到達規則）。

最後の1組を置いた時点で3列目12段目が埋まっていても構いません（置いた 2 個が連鎖で消え、4. を満たせばよい）。

盤面ごとに、最初に消える4個（発火点）と、条件6を満たす最後の1組を**すべて**出力します。

#### 到達規則

組は3列目に出現します（12段目が軸、13段目が子）。列の高さだけから、次の規則で届くかどうかを判定します。

- 11段以下の列は通れます。
- 13段の列（13段目まで埋まった列）は越えられません。軸は14段目に入れないためです。
- 12段の列は、軸を13段目に上げられる時だけ越えられます（壁越え）。上げ方は次の3つです。
  - 出現直後に2列目と4列目がともに12段以上（クイックターン）
  - ちょうど11段の列の上（床蹴り）
  - すでに乗った12段の列の上
- 上がった軸は、低い列を**4列まで**（6列の盤面では何列でも）またいで12段の列に乗れます。床蹴りは3列目の反対側の列で行ってもよく、その場合は戻る途中の列（3列目を含む）もまたいだ列に数えます。
- 縦置きは11段以下の列にだけ置きます（14段目に何も残さないため）。

クイックターン・床蹴り・12段の列からの1列またぎに加えて、床蹴りからのまたぎと2〜4列またぎを、実機でできる壁越えとして入れてあります（またぐ列数は `core/reach.h` の `MAX_HOP`）。

v0.3.0までの移動モデル（壁蹴り・床蹴り・クイックターンを幅優先探索、落下なし）が許す置き方と、この規則が許す置き方は一致します（`tools/compare_reach.cpp` で高さの組合せを全数比較。`MAX_HOP` が2だった v0.4.0 では、差は3列以上またぐ移動だけでした）。また、ゲーム側の1フレーム単位の操作処理（`game/control.h`）で実際に届く置き方とも一致します（`tests/frame_tests.cpp`）。

#### 保証しないこと

- **空盤面からその盤面を組み上げる手順は出力しません**（v0.3.0までは出力していました）。保証するのは「最後の1組を置けば発火する」ことだけで、そこまでの積み方は利用者に任せます。
- フレーム単位の自動落下、接地時間、入力受付時間、機種差はモデル化していません。特定ゲームのツモ列との照合は行いません。おじゃまは生成しません。

#### 各盤面は独立に生成します

1回の探索（試行）は、試行番号ごとに独立した乱数系列で、連鎖後に残る盤面から始めます。1回の探索から保存する盤面は最大1つです。見つかった盤面を少し変えて似た盤面を量産することはしません。過去の `19chain_urls.txt` と今回の実行中の同じURLは除外します。

### 探索の仕組み

連鎖を逆向きに伸ばします。連鎖後に残る盤面（余剰だけの、何も消えない盤面）から始め、1段ごとに「4個の組を列の途中へ差し込む」逆操作を行います。差し込んだ盤面で、(i) 差し込んだ4個以外に4個以上の連結がなく、(ii) 差し込んだ4個が周囲の同色とつながらない場合だけ採用します。すると、その盤面で消えるのは差し込んだ4個だけで、落下後は元の盤面に正確に戻ります。したがって n 回の逆操作で作った盤面は、必ず単独4個消し n 連鎖になり、最初に消えるのは最後に差し込んだ4個、連鎖後は出発点の盤面です。この性質は連鎖数・余剰個数・色数によりません。

このため、探索の内側では連鎖のシミュレーションを行いません。条件ごとの扱いは次のとおりです。

| 条件 | 探索中の判定 |
| --- | --- |
| 連鎖数・単独4個消し・発火点 | 作り方から必ず成り立つので判定しない |
| 連鎖後に3列目12段目が空 | 連鎖後の盤面は出発点そのものなので、出発点を作る時に3列目を11段までにする（余剰が11個以下なら自動的に成り立つ） |
| 14段目に置かない | 差し込み時に高さ13段以下を保つ |
| 最後の2個を除くと何も消えない | 「その2個が発火点の4個のどれかを含む」と同値。マスク演算で判定 |
| 最後の1組が出現できる・届く | 候補の組ごとに高さから判定 |

逆操作はビット演算で行います。列への差し込みは列ごとの乗算（シフト）、4個以上の連結の有無は「同色の隣があるか」の4枚のマスクから flood fill なしで判定します。候補位置は、発火点のピースを動かす位置と列の高さに合う位置のビット集合から直接求めます。

各段階では親盤面ごとに `candidates_per_parent` 個を一様に選び、`beam_width` 個まで残します（ビーム探索）。選ぶ時は候補を全て調べず、（位置・色）の組を乱数で引いて検査し、必要な数が見つかった時点でやめます。96回引いても足りない時だけ全て調べて残りから選ぶので、選び方は一様のままです。最終段の直前だけは全ての子盤面を残します。

#### ほぼ満杯の盤面での誘導

盤面がほぼ満杯だと、最後の1組を置ける場所はごく限られます。発火点のうち少なくとも1個は、最後の1組に含まれる位置（組が届く列の上から2個以内）になければなりません。列の高さだけから求めた、その発火点のピースがあり得る位置は次のとおりです（`—` は不可能）。

| 盤面の個数 | 1列目 | 2列目 | 3列目 | 4列目 | 5列目 | 6列目 |
| ---: | --- | --- | --- | --- | --- | --- |
| 78 | — | — | 12段目 | — | — | — |
| 77 | — | — | 11段目以上 | — | — | — |
| 76（19連鎖） | — | 12段目 | 10段目以上 | 12段目 | — | — |
| 75 | 12段目 | 11段目以上 | 9段目以上 | 11段目以上 | 12段目 | — |
| 72（18連鎖） | 9段目以上 | 8段目以上 | 6段目以上 | 8段目以上 | 9段目以上 | 10段目以上 |
| 68（17連鎖） | 5段目以上 | 4段目以上 | 2段目以上 | 4段目以上 | 5段目以上 | 6段目以上 |

さらに、最後の差し込みは1つ前の発火点のピースを動かす必要があるので、それ以前の発火点も表面近くにないと成立しません。そこで**72個以上の盤面に限り**、最終段の手前6段では「新しい4個の上に載る元のピースが、どれかの列で1個以下」の差し込みだけを使います。19連鎖・76個では試行の成功率が24%から52%に上がります。

誘導は生成される盤面の幅を狭めるので、理論上の制約がゆるい72個未満の盤面（余剰なしなら17連鎖以下）では使いません。72個以上かどうかは連鎖数ではなく個数で決まるので、17連鎖以下でも余剰が多ければ誘導します。誘導の有無にかかわらず、保存する盤面は全条件を検査します。

**保存する盤面には、上の導出に頼らず、全条件をそのまま検査します**（`verifySolution`）。さらに、C++とは独立したPythonのセル単位シミュレーター（`tests/verify_output.py`）が同じ条件を検査し、出力された「最後の1組」が条件を満たす組の全てと一致することも確認します。

試行は複数スレッドで並列に実行します。試行番号ごとに乱数系列が決まり、番号順に結果を確定するので、**同じ設定なら、スレッド数やコンパイラによらず同じ盤面を同じ順で生成します**（MSVCとGCCで2000件の一致を確認済み）。

### ジェネレーターの設定

| 項目 | 意味 | 同梱値 |
| --- | --- | --- |
| `field_columns`, `field_rows` | 盤面の列数と、消える段の数（その上に隠れた段が1段）。6と12、または10と18 | 6、12 |
| `target_chain` | 生成する連鎖数。1〜19（10列×18段では1〜47） | 19 |
| `target_success_count` | 今回新たに保存するユニークな盤面数 | 100 |
| `initial_seed` | 探索の乱数初期値 | 20261004 |
| `color_count` | 3、4（通常の対戦）または5 | 4 |
| `beam_width` | 各連鎖段階で保持する盤面数の上限 | 48 |
| `restarts` | 独立探索の最大回数（各回最大1件） | 100000 |
| `candidates_per_parent` | 各親から次段階に残す候補数 | 2 |
| `min_extra_pieces` | 最小個数に追加する個数の下限 | 0 |
| `max_extra_pieces` | 追加する個数の上限。最大 `78 - 4 * target_chain`（10列×18段では `188 - 4 * target_chain`） | 0 |
| `threads` | 探索スレッド数。0は自動（論理プロセッサ数の半分） | 0 |

`config.ini` はUTF-8（BOMあり／なし）で保存できます。`key = value` 形式で、空行と `;` / `#` 以降のコメントを無視します。`[Generator]` などのセクション見出しは読み飛ばします。未知のキー、重複、必須項目の欠落、不正な数値はエラーです。

- 必須は `initial_seed`, `color_count`, `beam_width`, `restarts`, `candidates_per_parent`, `target_success_count` の6項目です。省略時は `field_columns=6`, `field_rows=12`, `target_chain=19`, `min_extra_pieces=0`, `max_extra_pieces=0`, `threads=0` です。
- `initial_seed` は0〜18446744073709551615の10進整数です。ゲーム内のツモを再現する乱数シードではありません。
- `beam_width` を大きくすると1回の探索の成功率が上がり、その分1回の時間が増えます。毎秒の生成数はほぼ変わりません。
- `candidates_per_parent` を1にすると候補が広がらず、ほとんど成功しません。
- 余剰は `0 <= min <= max <= 78 - 4 * target_chain`。等しい値なら個数を固定し、異なる値なら各試行で範囲内から選びます。奇数個の盤面もそのまま生成します。
- `initial_seed` 以外の正の整数項目は最大2147483647、`threads` は最大256です。

例：77個の19連鎖だけなら `target_chain=19`, `min_extra_pieces=1`, `max_extra_pieces=1`。18連鎖で72〜78個なら `target_chain=18`, `min_extra_pieces=0`, `max_extra_pieces=6`。

保存先は**実行時の作業フォルダー**です。設定ファイルの場所は引数で指定できます。

```powershell
.\random_19_chain.exe C:\path\to\config.ini
```

終了コード: 目標達成は0、試行上限に達した場合は1（生成済みURLは残ります）、設定／入出力エラーは2です。

#### 出力の読み方

```
trigger cells (x from left, y from bottom, 1-based): (3,9) (3,10) (3,11) (3,12)
last pair options (V vertical, H horizontal): V(3,12)(3,13)
```

`trigger cells` は最初に消える4個、`last pair options` は最後に置く1組の候補です（縦置き V、横置き H。どれか1つを最後に置くと発火します）。座標は左からの列・下からの段で、1始まりです。

### 10列×18段の盤面

`config.ini` に `field_columns = 10` と `field_rows = 18` を書くと（GUIでは「盤面」で「10列×18段」を選ぶと）、10列×18段の盤面で生成します。

- 消えるのは下の18段です。その上の19段目は隠れた段で、連結・消去には参加せず、下が消えると落下します。20段目には何も置きません。
- 組は左から5列目に出現します。5列目か6列目の18段目が埋まると負けになるので、連鎖後と、最後の1組を置く前の盤面では、この2つのマスが空いています。最後の1組を置いた時点では埋まっていても構いません。
- 届くかどうかの判定（到達規則）は、6列の盤面の規則の段数をずらしたものです（17段以下の列は通れる、19段の列は越えられない、18段の列は軸を19段目に上げた時だけ越えられる）。5・6列目が17段まで埋まっていれば床蹴りで上がれます。
- 連鎖数は1〜47です。最後の1組を置く前は5・6列目が17段までなので、盤面に入るのは最大 `8 × 19 + 2 × 17 + 2 = 188` 個、`188 ÷ 4 = 47` 連鎖です。余剰は `0 <= min <= max <= 188 - 4 * target_chain` です。
- 各波が同時消しなしの単独4個消しであること、最後の1組を置くと発火することなど、上の「生成される盤面の条件」は同じです。

10列×18段の盤面を表せる外部の連鎖シミュレーターがないので、URLは出力しません。代わりに、盤面を1行で表した**盤面コード**を `boards_10x18.txt` に追記し、重複の除外にも使います。盤面コードは `10x18:` に続けて、19段目から1段目へ、各段を左から右へ、190マスを `.`（空）と `R G B Y P` で並べたものです。CLIの出力は6列の盤面と同じ形で、盤面の前に `field=10x18` の行が入り、`URL:` の行の代わりに `board code:` の行が出ます。GUIでは結果の表示・連鎖の再生・盤面編集ができます（[GUI_README.md](GUI_README.md)）。

#### 探し方

探索の仕組みは6列の盤面と同じ逆向きの差し込みです。盤面の型は、1列を32bitの1語で持つ別の型（`generator/grid_field.h`）を使い、探索は同じ手順をどの大きさの盤面にも使えるように書いたもの（`generator/grid_generator.h`）です。6列×13段の盤面でこちらの探索を動かすと、試行ごとに今の探索とまったく同じ盤面を作ることを試験で確かめています（`tests/grid_tests.cpp`）。

空きがほとんど残らない盤面（使わないマスが20以下）では、そのままでは最後の1組で発火する形になりません。そこで、次の決まりを足しています。

- 最後の12段より前は、5・6列目から2列より遠い列を先に埋め、5・6列目とその両側2列には、最後の12段で埋める分の空きを残します。
- 最後の12段では、5・6列目とその両側2列のどれかで、新しい4個の上に載る元のピースが1個以下になる差し込みだけを使います。
- 各段で残す盤面は、空きを5・6列目からの距離で重み付けした量が少ないものからです（同じ量の中では無作為）。
- 余剰が78個以上の時は、余剰のピースを5・6列目から遠い列から順に置きます。
- 3色では、差し込む4個の色が周りのどのピースの色とも違わなければならないので、差し込める所が少なくなります。そのため3色の時だけ、決まりを次のように変えます: 5・6列目の近くに空きを残す決まりは使わず（盤面全体を「近く」とする）、次の段で何も差し込めない盤面は残さず、残す盤面の順位に隣の列との高さの差を大きく足し（深く細い空きは縦の4個でしか埋められないため）、最後の6段では残す盤面を4倍にします。3色の46連鎖では、4色と同じ決まりだと300回で0件、3色の決まりでは119件見つかりました。4色・5色にもこの決まりを使うと、1回あたりに見つかる数は増えますが、1回が5〜7倍遅くなり、1秒あたりでは減るので使いません。

決まりの値は `tools/grid_bench.cpp` で測って選びました（数値は `generator/grid_field.h` の注記）。たとえば47連鎖・4色では、決まりがないと300回の試行で0件、決まりを入れると200回で50件見つかりました。

#### 保証しないこと・弱いところ

1〜47連鎖 × 3/4/5色 × 余剰（0個・1個・上限・0〜上限）の555設定を、各設定1件、試行2万回か60秒までで生成してみた結果（2026-10-17、4スレッド。3色は v0.9.4 の3色の決まりで測り直した結果）:

- 4色と5色は、すべての設定で見つかりました。
- 3色は、余剰が0個・1個・0〜上限の設定はすべて（47連鎖を含む）見つかりました。
- 3色で余剰を上限にした設定（連鎖後の盤面がほぼ満杯）は、8・9・19・20・22・24〜27連鎖で見つかりませんでした。余剰のピースの色を無作為に決めるので、残りの空きの周りに3色が入り混じり、差し込める色がなくなるためと考えています（確かめてはいません）。

## ビルドとテスト

Visual Studio 2022 などの C++20 コンパイラーと CMake 3.16 以降を使います。x64 では SSE4.1 と POPCNT を使います（PEXT/PDEP は実行時に CPU を判定して使い分けます）。それ以外の CPU 向けに 64bit 演算だけの実装も入っています（`core/field_bits.h`）。盤面ジェネレーターの GUI は Windows（MSVC）だけです。ゲーム本体は Windows では Direct2D・XAudio2 で、Linux では SDL 3 で動きます（下）。ジェネレーターの CLI、AI のツール（`ai_match` など）、盤面コア・ゲーム・AI・通信のテストは GCC と Clang でもビルドできます。macOS では、ゲーム本体はアプリ（`JuraicField.app`）になります。GitHub Actions の `.github/workflows/macos.yml` が、Apple シリコンの Mac でビルドとテストを行います。Android 版は `android/`（Gradle）で作ります。SDL 3 の配布物を展開したフォルダーを `-PsdlSource=` で渡し、SDL の Android 用の部品（Java と Gradle のラッパー）もそこから使います。手順は `.github/workflows/android.yml` にあります。

```powershell
cmake -S . -B build
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
cd build/Release
.\JuraicField.exe
```

性能測定は必ず **Release** で行ってください。ビルドすると、`media/` の絵と曲が exe の隣（`background`・`bgm`）に写されます。

Windows では、SDL 3 があると、PlayStation のパッドと Switch の Pro コントローラー・Joy-Con をそれで読みます。これらのパッドは、ほかのソフトに頼まれると独自の形で送るようになり（Pro コントローラーは USB では必ず）、Windows の汎用の読み方では、押していない方向やボタンが押されているように読めてしまうためです。SDL 3 が無くてもビルドはでき、その時はこれらのパッドも汎用の読み方で読みます。SDL 3 は静的ライブラリーとしてビルドし、`CMAKE_PREFIX_PATH` で指します。

```powershell
# SDL 3（https://github.com/libsdl-org/SDL/releases の SDL3-3.4.18.tar.gz を展開したフォルダーで）
cmake -S . -B build -A x64 -DSDL_SHARED=OFF -DSDL_STATIC=ON -DSDL_TESTS=OFF -DCMAKE_MSVC_RUNTIME_LIBRARY=MultiThreaded -DCMAKE_POLICY_DEFAULT_CMP0091=NEW -DCMAKE_INSTALL_PREFIX=C:/sdl3
cmake --build build --config Release
cmake --install build --config Release

# Juraic Field
cmake -S . -B build -DCMAKE_PREFIX_PATH=C:/sdl3
```

Linux では、SDL 3 があればゲーム本体もビルドされます（無ければゲーム本体だけを飛ばします）。SDL 3 は静的ライブラリーとしてビルドしておき、`CMAKE_PREFIX_PATH` で指します。絵・曲・文字の読み込みに使う 1 ファイルのライブラリー（stb_image・stb_truetype・dr_flac・dr_mp3・dr_wav）は `third_party/` に入っています。

```bash
# SDL 3（https://github.com/libsdl-org/SDL/releases の SDL3-3.4.18.tar.gz を展開したフォルダーで）
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DSDL_SHARED=OFF -DSDL_STATIC=ON -DSDL_TESTS=OFF -DSDL_X11_XTEST=OFF -DCMAKE_POSITION_INDEPENDENT_CODE=ON -DCMAKE_INSTALL_PREFIX=$HOME/sdl3
cmake --build build && cmake --install build

# Juraic Field
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_PREFIX_PATH=$HOME/sdl3
cmake --build build
ctest --test-dir build --output-on-failure
./build/JuraicField
```

Ubuntu 22.04 で SDL 3 のビルドに要る開発用パッケージ: `cmake ninja-build pkg-config libasound2-dev libpulse-dev libpipewire-0.3-dev libx11-dev libxext-dev libxrandr-dev libxcursor-dev libxfixes-dev libxi-dev libxss-dev libxkbcommon-dev libwayland-dev libdecor-0-dev libdrm-dev libgbm-dev libgl1-mesa-dev libgles2-mesa-dev libegl1-mesa-dev libdbus-1-dev libudev-dev`。Linux では、ビルドするとフォント（`media/fonts`）も `fonts` に写されます。
